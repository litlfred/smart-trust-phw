scripts/ cat-harness-tools-scripts

Scripts this layer runs. `lib/roots.ts` is the one place that names the three roots a file can mean (HARNESS_ROOT, TOOLS_ROOT, REPO_ROOT). `gen-id-lookup.ts` builds the prefix-sharded lookup over a catalogue's REFERENCED nodes for every instance that declares an `id-lookup` directory, and writes it THERE (`bun run cat id-lookup`, gated by `id-lookup:check`); `bench-id-lookup.ts` measures it at full catalogue scale on a seeded synthetic corpus. Neither names a corpus: both read the checkout's declarations. `extract-assets.ts` is the tool behind the harness's `asset-extraction` skill: it turns a container's INDEX into a `folio-extraction/v1` record, whose contract is `schemas/content/extraction.ts`.

upstream/ cat-harness-tools-upstream

This layer's pinned-upstream registry, `upstream-pins.json` (`"$schema": "folio-upstream-pins/v1"`): one row for each upstream dependency whose pin literal is in a file this layer holds (today only the pdf.js viewer, pinned in `scripts/pdf-viewer.ts`). Each row names the file the pin is READ from (`pinnedIn`, resolved against this instance's root), the pattern that reads it, and what of ours binds to the dependency; it holds no version. `bun run cat check:upstream-pins` reads it together with cat-harness's `upstream/` registry (`cat-harness-upstream`), which keeps the rows whose files are in the harness, since a harness row naming a file in this layer would be a wrong-direction reference. `code`: the checker's input table, not content any reader renders.
